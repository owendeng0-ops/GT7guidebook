# GT7 Track Atlas V1.4：遥测可用性与训练归档

## 目标

V1.4 把 V1.3 的“能实时读取遥测”推进到“可以日常练车使用”。核心不是自动替玩家做所有决定，而是把关键链路变清楚：

1. 是否连接上本地 telemetry-agent。
2. 是否收到 PS5 / GT7 遥测。
3. 完成圈是否已经可靠保存。
4. 这圈应该归档到哪个 layout。
5. 归档后训练记录是否带有可复盘摘要。

## 状态中心

主站遥测面板常驻显示状态提示：

- `未检测到 agent`：本地 `telemetry-agent` 未启动，主站保持手动模式。
- `等待 PS5`：agent 已启动，但尚未收到 GT7 UDP 包。
- `解密失败`：收到 UDP 包但无法解析，可能是包格式变化或非 GT7 数据。
- `实时在线`：收到并解析 GT7 遥测，车速、油门、刹车、挡位实时更新。
- `遥测中断`：超过 5 秒没有新包，通常是退出驾驶、网络切换或防火墙阻断。

面板会展示启动命令、同网段、驾驶画面、防火墙、端口占用等排查建议，并提供 `/health` 快捷入口。

## 数据保存

V1.4 明确拆分短摘要和长 trace：

- `localStorage`
  - 训练摘要
  - 用户偏好
  - 待归档遥测圈列表

- `IndexedDB gt7-track-atlas-telemetry-v1`
  - `lap-traces`：`traceId`、降采样 trace、lap summary、采集时间、归档 layout
  - `layout-templates`：用户绑定的 layout fingerprint 模板

这样可以避免把长 trace 塞进训练摘要层，也能让刷新页面后待归档圈不丢。

## 待归档流程

`lap_completed` 到达后不会直接写入当前网页 layout，而是进入“待归档遥测圈”：

1. agent 推送 `lap_completed`。
2. 主站保存降采样 trace 到 IndexedDB。
3. 主站把 lap summary 写入 pending 列表。
4. 用户确认后点击“归档到当前布局”。
5. 训练记录新增 `Telemetry Auto` session。
6. pending 列表移除该圈，trace 记录写入 `archivedLayoutId`。

这个流程牺牲了一点自动化，但避免了当前网页 layout 与 PS5 实际 layout 不一致时误归档。

## 布局模板与置信度

GT7 遥测包中目前没有可靠公开的 `trackId/layoutId`。V1.4 采用本地模板识别：

1. 用户确认某一圈和当前网页 layout 一致。
2. 点击“绑定为当前布局模板”。
3. 主站把这圈位置 trace 归一化为 fingerprint。
4. 后续完成圈与本地模板比对，输出推荐 layout 和置信度。

置信度策略：

- `>= 0.85`：建议归档。
- `0.65 - 0.85`：需确认。
- `< 0.65`：未知布局。

如果推荐 layout 与当前网页 layout 不一致，归档按钮会触发冲突确认。

## 训练记录复盘

遥测归档后的 session 会显示：

- `Telemetry Auto` 标签。
- `traceId`。
- 单圈时间。
- 极速、均速。
- 刹车事件次数。
- 全油占比。

第一版只展示轻量摘要，不做复杂曲线图。后续 V1.5/V1.6 可以在此基础上加入弯角级分析、setup 对比和参考 telemetry 对比。

## 验收点

- agent 未启动时主站显示明确提示，手动记录仍可使用。
- PS5 不在线时显示等待状态与排查建议。
- 实时在线时车速、油门、刹车、挡位更新。
- 完成圈后 pending 列表出现 lap card，刷新页面后仍存在。
- 归档后训练记录出现 `Telemetry Auto` session。
- 绑定模板后，后续相似 trace 能显示推荐 layout 和置信度。
- 推荐 layout 与当前 layout 不一致时，归档前出现冲突确认。
